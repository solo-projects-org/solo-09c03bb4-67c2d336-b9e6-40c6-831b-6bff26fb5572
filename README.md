# 住户能源调查 · 权重校准台账

固定样本 CSV → 按街道 / 住房类型精确校准户数 → 发布逐户权重；已交付街道可锁定，锁定值跨发布保留。
按月补报各户用电量（Wh），按（月份、街道、电量值）累计现行权重形成分布，网页直接给出
每条街道的高用电水平（P90）与已报 / 全部样本权重合计，供调查组比较各街道。
FastAPI + SQLite，单页服务端渲染，Docker Compose 启动。

## 快速开始

```bash
docker compose up --build -d
# 打开 http://localhost:8000
```

端口可用 `CALIBRATION_PORT=8080 docker compose up --build -d` 覆盖。

- 数据保存在命名卷 `calibration-data` 的 SQLite 文件中，`docker compose down`
  不会删除；`docker compose down -v` 才会连同数据一起清掉。
- 首次启动时用 `data/sample.csv`（固定样本，含样本号 / 街道 / 住房类型 / 正整数初始权重）
  灌入 200 户，现行权重＝初始权重。之后重启不会重复导入或覆盖。

不用 Docker 时：

```bash
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --port 8000
```

测试：

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q
```

## 使用流程

1. **概览**：样本户数、初始 / 现行权重合计、已锁定街道数、成功发布次数、已入库读数与覆盖月份。
2. **用电读数补报**：选择账单月份（YYYY-MM），上传含「样本号、用电量」两列的 CSV
   （用电量为非负整数，单位 Wh；表头接受常见中英文别名）。
   - 同户同月以**最后成功入库**的读数为准（覆盖写）。
   - 批内样本号重复、样本号不在固定样本中、用电量非法、月份格式错误：
     **整批退回**，账单、分布、批次记录都不变。
   - 每个被接受的批次都会留一条批次记录（月份、行数、新增 / 覆盖户数、入库时间）。
3. **各街道月度用电水平**：下拉切换月份，逐街道列出
   已报户数、**已报样本权重合计**、**全部样本权重合计**、覆盖率与**高用电水平（P90，Wh）**；
   当月无读数的街道标为**未报**。
   - P90 直接从分布按电量从低到高累计现行权重，取累计权重**首次达到或超过已报权重 90%**
     的电量值（整数运算：`10 × 累计 ≥ 9 × 已报合计`）。
4. **锁定街道**：下拉选择街道 → 锁定其**当前逐户权重**。发布前锁定即锁定初始值，
   发布后锁定即锁定最近一次发布的权重。重复锁定同一街道不会改变锁定值。
   锁定后，该街道的权重与合计在后续发布中保持不变，目标框显示为只读。
5. **设定目标户数**：分别填所有未锁定街道和目标住房类型的户数，点击「校准并发布」。
   - 两套目标必须**分别精确达标**。
   - 每户新权重为 **正整数且 ≤ 2 × 该户初始权重**（下限为 1）。
   - 锁定街道逐户取锁定值，因此它的合计也随之固定。
6. **发布**：所有约束同时可满足才会一次性写入全部逐户权重并留下发布记录；
   否则页面显示**一组极小冲突**（去掉其中任意一项，其余条件即可同时满足），
   且现行权重与发布记录都**不变**。
   - 首次发布前分布使用初始权重；发布改变一户权重后，该户**所有已报月份**的分布项
     在同一事务内刷新为新权重。

页面底部的「查看逐户现行权重」可展开核对每户初始值与现行值；重启服务后这些数据仍在。

## 分布与一致性保证

- **分布表** `distribution(month, street, usage_wh, weight_sum)` 是物化的现行权重累计，
  只增量化维护：补报只动被覆盖账单对应的（月份、街道、电量）项；发布只动权重有变化
  且已报账单的户所涉及的项。权重变为 0 的项即删除，绝不留空项。
- **一次生效**：账单 + 分布、权重 + 分布分别在**同一个 `BEGIN IMMEDIATE` 事务**里提交；
  任一步失败整体回滚，不会出现账单已改而分布未改的中间态。
- **交错可复算**：补报与发布任意交错后，网页查到的分位数与覆盖都能从
  同一份已提交的账单和权重重新算出相同结果（测试里每次写入后都用全量重算对拍）。
- **重启可查**：全部状态在 SQLite（WAL）中，重启服务后账单、分布、权重、锁定、
  发布与批次记录原样可读。

## 冲突提示语义

无解时返回的冲突集合由若干「条件」组成：

- `街道「X」目标户数 = N`：某未锁定街道的目标；
- `住房类型「T」目标户数 = N`：某住房类型的目标；
- `街道「X」锁定（…）`：某街道的锁定逐户权重。

该集合整体无解，而任意删去其中一条后剩余条件都有可行解，因此可以直接指出
"改这几个目标 / 放开某个锁定"这一最小修复方向。1 倍～2 倍初始权重、权重为正整数属于
不可放开的基础规则，不列入冲突集合。

## 实现要点

- `app/solver.py`：把校准问题写成街道—住房类型二分图上的整数运输问题。
  每户权重区间为整数 `[lower, upper]`，各街道与各类型的户数和为等式约束。
  约束矩阵是全幺模的，因此用带下界的最大流（Dinic + 下界平衡）即可判定
  整数可行性并直接得出整数解。冲突集合用贪心删除法求解极小不可行子集，
  每次删除都调用同一套流算法验证。
- `app/db.py`：SQLite 持久化。发布在单个 `BEGIN IMMEDIATE` 事务里完成
  锁定快照读取 → 求解 → 更新 → 刷新分布 → 写发布记录，失败即回滚；
  补报在同样的事务里完成批次校验 → 账单覆盖写 → 分布增减 → 批次记录。
  分位数用纯整数运算（`10 × 累计权重 ≥ 9 × 已报合计`）避免浮点误差。
- `app/main.py` 与 `app/templates/index.html`：FastAPI 路由 + 服务端渲染表单，
  补报 / 发布成功 303 跳转并提示，冲突返回 409 并列出冲突项，输入错误返回 400。
- 样本导入在启动时进行，表头接受中文列名；重复样本号、非正整数权重、
  缺失列都会在导入时报错。读数 CSV 同样接受别名表头与 UTF-8 BOM。

## 已知限制

- 单进程 / 单用户场景设计：SQLite 以 `BEGIN IMMEDIATE` 串行化写操作，
  未做多租户或账号体系。
- 极小冲突集不唯一，返回的是按当前排序贪心删除得到的一组；它是有效的最小修复提示，
  但不保证是"唯一"或"条目数最少"的那一组。
- 目标户数的上限被限制在 10 亿（`MAX_TARGET`）以内，超出给出错误提示。
- 样本为固定 CSV，网页不提供增删样本的入口（符合"导入一份固定样本"的要求）。
- 上传 CSV 限制 5 MB / 20 万行以内；账单月份按 `YYYY-MM` 校验，不做日历合理性判断。
